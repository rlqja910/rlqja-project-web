1. **프론트엔드 작업 시 주의사항 (서브모듈 구조 인식):**
   - 현재 프로젝트는 루트 폴더와 `frontend-app` 폴더가 동일한 깃허브 원격 저장소를 바라보는 구조로 꼬여있으며, **실제 Vercel 배포는 `frontend-app` 폴더 내부를 기준으로 동작**합니다.
   - 따라서 프론트엔드 코드 수정은 반드시 `frontend-app` 폴더 내부의 파일(`frontend-app/src/...`)을 직접 수정해야 하며, `git add`, `git commit`, `git push` 명령어 역시 **반드시 `cd frontend-app` 으로 이동한 상태에서 실행**해야 합니다. 루트 폴더에서 푸시할 경우 Vercel 배포 시 최신 코드가 반영되지 않는 치명적인 에러가 발생합니다.
   - 절대 백엔드 폴더(dashboard-app)나 파이썬(python-worker) 폴더를 프론트엔드 레포지토리에 커밋하지 마세요.
2. **커밋 메시지 규칙:**
   - 커밋 메시지는 무조건 **한국어**로 작성한다. (예: "feat: 관리자 로고 클릭 기능 제거", "fix: 버튼 스타일 수정")
3. **타입스크립트 검증 및 Vercel 배포 연동:**
   - Vercel은 빌드 시 사용하지 않는 변수(unused variables) 등 작은 TypeScript 에러만 있어도 배포를 실패(Crash) 처리합니다.
   - 깃 커밋 전에 반드시 로컬에서 에러가 없는지 점검하거나, 필요 없는 변수를 꼼꼼히 삭제하세요.
   - 커밋/푸시 후에는 반드시 화면 배포(Vercel CLI: `npx vercel --prod --yes`)를 즉시 실행해야 하며, 배포가 성공적으로 완료되었는지 상태를 확인한다. 배포 실패 시 즉시 원인을 파악하고 코드를 수정하여 재배포한다.
